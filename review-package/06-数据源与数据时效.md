# 数据源与数据时效

## 当前数据分层

| 层 | 例子 | 进入 P0 的方式 | 失败语义 |
| --- | --- | --- | --- |
| 持仓 | 批准后的本地 portfolio JSON | after-close 读取并映射 | 缺失保持 unknown |
| 市场风险 | risk-watch | 最新本地报告 | stale/missing/blocked |
| 市场脉冲 | market-pulse | 最新本地报告 | stale/missing |
| 关键价位 | market-levels | 最新本地报告 | stale/missing |
| 产业研究 | ai-capex-watch 等 | 最新本地报告 | stale/missing |
| 公告/财务 | CNInfo、AmazingData 等 | 由现有工作流消费 | 失败不得由 AI 补写 |
| 用户回应 | 本地 JSONL | 计划 id + version 范围 | 版本不匹配不恢复 |
| 计划版本 | 本地 JSONL | 内容寻址版本 | 内容未变不重复写 |

## 时效原则

- 盘后生成记录 `source_generated_at` 和有效市场日期；
- 晨间复核只对同一来源报告重新判断新鲜度；
- 没有实时刷新证据时，不声称行情已更新；
- 刚发布的 A 股关键公告优先查 CNInfo，同日晚间应覆盖次日公告日期；
- unknown、stale、missing、blocked 不按零、正常或已确认处理。

## AI 数据边界

P0 不调用 AI 生成交易计划。未来若启用解释型 AI，输入证据摘要应有稳定 hash；证据不变读取缓存，不重复调用。AI 输出不能更改结构化规则、来源时间或阻断状态。

## 分享包脱敏

`artifacts/` 中的 HTML 使用合成持仓、合成代码和临时响应账本。真实报告路径只用于本地验收，不复制到包内。
