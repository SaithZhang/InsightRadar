# 技术架构与核心代码

## 运行形态

- Windows 本地单用户；
- Python 3.13 项目虚拟环境；
- 单文件 HTML，无前端构建步骤或外部资源；
- loopback 服务绑定 `127.0.0.1`，写操作需要随机会话 Token；
- JSON/JSONL 为 P0 持久化。

## P0 关键文件

| 文件 | 责任 |
| --- | --- |
| `stock_assist/workflows/after_close.py` | 汇总持仓、市场和研究结果 |
| `stock_assist/decision_workspace.py` | 计划、响应、版本、状态不变量 |
| `stock_assist/after_close_workbench_html.py` | 冻结四页 renderer 与交互 |
| `stock_assist/portfolio_import_server.py` | loopback 页面和受控写 API |
| `stock_assist/portfolio_import.py` | 持仓预览、批准、备份、原子保存 |
| `data/decision_workspace_plans.jsonl` | 本地计划版本历史 |
| `data/decision_workspace_responses.jsonl` | 本地用户回应 |

## 写接口

`POST /api/plan-response`

- 校验会话 Token；
- 从服务器当前 workspace 查找精确 `plan_id + plan_version`；
- 使用服务器计划状态校验回应；
- blocked + accepted 失败关闭；
- 原子追加本地 JSONL。

`POST /api/morning-recheck`

- 不重新编计划；
- 仅重判当前来源时效；
- runtime state 与原始报告时间绑定。

## 状态集合

- 计划：`new / revised / unchanged / voided / blocked`
- 回应：`pending / accepted / disputed / rejected / deferred / blocked_acknowledged`
- 数据：`ready / stale / missing / blocked / pending / failed`

## 分享快照生成

`review-package/build_scope_frozen_snapshot.py` 使用生产 renderer 和状态模块，但构造全合成持仓与临时 ledger，生成不含用户私有数据的可交互 HTML。
