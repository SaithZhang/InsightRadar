# InsightRadar 个人量化模型 MVP

## 模型选择

首版固定使用 CPU 版岭回归 `Ridge v1`，不使用GPU和深度学习。原因是当前只有日线、少量股票和少量因子，岭回归训练只需数秒，权重可以审计，也能完整回放。模型暂时使用7个因子；原始账本仍保留8个因子，Amihud因子因与流动性高度共线而不进入首版模型。

## 每日闭环

1. 交易日15:40后拉取完成的日K；未收盘K线不写入。
2. 先使用期间历史代码并集计算滚动因子，再按当日有效成员过滤；按 `universe_id + date + code` 幂等写入 `observations.csv`。
3. T日样本先保持 `pending`；只有完整走过5个交易日，才能写入相对中证1000收益标签。
4. 使用最近约252个交易日的成熟样本全量重训候选模型。
5. 使用独立尾部验证集检查RankIC、IC胜率、扣费Top-Bottom、五分层单调性、VIF与条件数。
6. 全部硬门槛通过且质量分优于冠军时，才原子替换 `champion.json`；否则只登记候选版本。
7. 没有冠军模型时，任何排名都必须标记为诊断，不得接入交易动作。

## 本地文件

- `data/factor_pipeline/observations.csv`：私有特征与成熟标签账本。
- `data/factor_pipeline/models/*.json`：每个数据/模型规格对应的候选版本。
- `data/factor_pipeline/champion.json`：唯一允许进入正式评分的冠军模型。
- `data/factor_pipeline/registry.jsonl`：去重的模型审计记录。
- `data/factor_pipeline/scheduled-run.log`：计划任务运行日志。
- `data/factor_universe/csi1000_membership.csv`：中证1000历史纳入/退出区间，带来源、获取时间和可复现哈希。

这些文件均为本地私有运行数据并被Git忽略；可提交的是配置、代码、测试和Schema。

## 成本路线

- 阶段1：20至300只股票、日线、几十个因子。本地CPU每日重训，新增算力成本接近0。
- 阶段2：扩大到全中证1000和5至10年历史。仍优先本地批处理；使用Parquet替换CSV以降低IO。
- 阶段3：只有当分钟级数据、数千因子或单次训练超过约30分钟时，才迁移到按任务启动的云CPU实例；训练结束立即释放，不保留常开服务器。
- GPU只在样本规模、稳定基线和消融实验共同证明非线性模型有增益后考虑。

## 当前硬限制

历史中证1000成员区间和股票池血缘已经可用；默认20股配置仍保留为独立的显式试验池。尚未完成行业/市值中性化、ST/新股过滤、涨跌停可交易性、自由流通市值权重和真实冲击成本，因此模型仍不得直接产生交易指令。
