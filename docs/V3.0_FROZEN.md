## Runtime Shape

InsightRadar V3 is a local Python application. `after-close` generates one canonical JSON payload plus Markdown and self-contained HTML renderers. `portfolio-import --serve` exposes the newest workspace at `http://127.0.0.1:8765/`.

The four frozen first-level tasks are:

| Route | User label | Current code reality |
|---|---|---|
| `#today` | 今日计划 | Implemented. Shows the prior after-close plan, morning freshness restage, market gate, pending plan changes, risk/data cards, and human response controls. |
| `#portfolio` | 组合风险 | Implemented. Shows known exposure, unknown weight/beta, reconciliation blockers, data completeness, strict readiness, and holding-level plans. |
| `#lookup` | 标的研究 | Partially implemented. It records research intent and exposes existing evidence/market permission. Real technical charts and P1 research orchestration are explicitly absent. |
| `#review` | 复盘账本 | Partially implemented. It shows plan-version history, user responses, and existing T+1/T+5/T+20 outcome maturity. Real trade execution and full regime attribution are not connected. |

There is no fifth route. Detailed market evidence is a drawer and an upstream decision input.

## “今日计划” Organization

The current home page is organized in this order:

1. **Generation chain:** prior after-close plan, morning freshness restage, and authority boundary.
2. **Market constraint:** current stance/risk gate before any holding action.
3. **Portfolio-related themes:** diagnostic-only theme state and freshness.
4. **Primary changed plan:** the most urgent pending actionable plan.
5. **Remaining queue:** every other pending actionable plan; blocked plans cannot be accepted.
6. **Side rail:** risk budget, source health, and unimplemented monitor handoff.
7. **Human response:** accept, dispute, reject, defer, or acknowledge a blocked version.

Morning restage currently recalculates freshness against the same source report. It is not a live market refresh.

## Service at 127.0.0.1:8765

`stock_assist.portfolio_import_server` uses `ThreadingHTTPServer` and binds only to `127.0.0.1`.

- `GET /`: newest four-route decision workspace.
- `GET /portfolio-import`: local paste/preview/approval import UI.
- `GET /api/workspace`: current overlaid workspace.
- `POST /api/plan-response`: version-scoped user response.
- `POST /api/morning-recheck`: freshness-only restage.
- `POST /api/preview`: read-only broker TSV preview.
- `POST /api/apply`: explicit approved save followed by serial refresh.
- `POST /api/shutdown`: local process shutdown.

State-changing requests require an unguessable in-page session token. The service does not accept trade orders.

## Historical Freeze Boundaries

- Preserve the four task routes and responsibility boundary.
- Do not copy sample values from prototypes into runtime.
- Do not add P1/P2 features during the ten-run pilot.
- Only data errors, plan mismatches, state-persistence failures, security issues, and core-flow blockers may change the runtime.
- No automatic trading or AI strategy authority.

These bullets describe the V3.0 trial constraint. The four-route, truth-labeling, human-confirmation, privacy, and no-automatic-trading rules continue as V3.1 product guardrails under `docs/PRODUCT_BASELINE.md`.
