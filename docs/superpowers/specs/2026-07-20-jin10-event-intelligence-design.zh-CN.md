# 金十事件情报层设计（人工 Review 副本）

> 本文仅供中文人工审阅，不是规范性来源。英文版 [2026-07-20-jin10-event-intelligence-design.md](2026-07-20-jin10-event-intelligence-design.md) 是 AI 指引与后续实现的唯一正式规格；两者不一致时以英文版为准。

- 状态：已确认
- 日期：2026-07-20
- Feature：`feat-055`
- 实现状态：未开始

## 最终选择

采用独立事件情报层，不把金十响应直接塞入 `after-close`：

`金十发现 → 标准事件 → 分类去重 → 官方确认 → 持仓/市场相关性 → 影响评估 → 报告或关键预警`

金十负责速度，不负责最终事实权威，也没有独立交易授权。`feat-055` 排在 `feat-044` 后面，不改变当前下一项工作。

## 为什么需要这一层

原始快讯流有三个问题：重要事件可能因为搜索词不对而漏掉；“国家队”等词会混入体育和产业噪声；即使新闻是真的，也可能把历史累计金额误读成明日新增资金。

InsightRadar 需要的是“重要事件是否改变当前计划”，不是更多新闻数量。

## 首期范围

包含：

- 通过标准 MCP 获取金十快讯、资讯详情和财经日历；
- 机器只读取 `structuredContent`；
- 使用 `cursor / data.next_cursor / data.has_more` 分页；
- 事件标准化、去重、实体/动作/资产分类；
- 将周末、开盘前、午间、盘后等“重要消息汇总”识别为校漏检查点，而不是重复的新事件；
- 区分新增成交、近日累计、历史累计、未来承诺和未知；
- 对重要政策、公告和国家资金事件保留官方确认状态；
- 优先映射已批准持仓，无持仓时映射市场、指数、风格和行业；
- 通过证据门槛后进入统一报告或关键预警；
- 明示限流、过期、冲突、缺少确认和服务异常。

不包含：

- 自动交易或标题驱动的买卖指令；
- 用新闻条数直接生成市场分数；
- 用金十替代巨潮、交易所、政府部门或公司官网；
- 首期重复建设报价和 K 线能力；
- 立即建设多数据源事件总线、云服务或实时推送基础设施。
- 在 MCP 没有结构化重要等级时，逆向猜测 APP 的加红样式或重要性。

## Codex 与独立产品的边界

当前 Codex 已经能够调用金十 MCP，这只证明数据源可用，也方便开发阶段分析。未来 InsightRadar 独立运行时不能依赖 Codex 的个人配置。

产品实现必须自带标准 MCP 客户端，完成：

1. `initialize`（协议 `2025-11-25`）；
2. `notifications/initialized`；
3. `tools/list` 和 `resources/list`；
4. 有边界的 `tools/call`；
5. 会话复用、超时和重连。

Token 只从仓库外的 `JIN10_MCP_TOKEN` 环境变量读取，不得进入 Git、报告、日志、测试样例或异常文本。

## 事件必须记录什么

- 稳定事件 ID、来源 ID、来源链接；
- 发布时间、获取时间和时区；
- 原始正文和规范化事实摘要；
- 机构、动作、资产、市场/风格/行业标签；
- 金额、单位及金额语义；
- 官方确认状态、官方链接、冲突和缺口；
- 与其他重复快讯或晚间汇总的关系；
- 原子事件或 digest 容器类型、汇总时段以及子事件关系；
- 金十重要/加红状态及字段来源；服务未提供时必须保持未知；
- 对持仓或市场的相关性、作用期限、正反传导路径；
- 是否进入背景资料、报告或关键预警。

不同语义的金额绝不合并成“新增资金”。例如：

- 中国国新“已经使用超500亿元”属于已使用的累计规模，不能写成明日新增500亿元；
- 中国诚通“近日累计买入近百亿元”属于近期累计成交，同时还包含未来继续增持的意图；
- 两者都不能在缺少期间和成交明细时直接相加成明日买盘。

## 重要消息汇总与加红信息

金十每天可能多次发布高密度汇总，周末、下一交易日开盘前、午间、盘后和晚间尤其值得关注，例如[“周日重要消息汇总”](https://flash.jin10.com/detail/20260719225915777800)。这类内容适合作为高效校漏检查点。

汇总本身不是一个新的市场事件。产品需要：

1. 根据标题和正文识别汇总类型及发布时间，不假定发布时间永远固定；
2. 将编号或明确分隔的内容拆成子线索，同时保留原汇总链接；
3. 将每条子线索与已经获取的原子快讯核对；
4. 已存在的事件只增加汇总关联，只有真正遗漏的内容才新增线索；
5. 用汇总衡量漏报情况，不能借此增加事件数和预警数。

2026-07-20 实测 `search_flash("重要消息汇总")` 返回52条。所有结构化快讯条目的字段合集只有 `content/time/title/url`；目标“周日重要消息汇总”本身只有 `content/time/url`。当前没有 `importance`、`is_red`、`hot_level`、标签或显示样式字段。

因此目前无法可靠区分金十 APP 的“加红信息”。产品必须把 `provider_importance` 和 `provider_red_highlight` 保持为未知并暴露数据缺口，不能根据措辞、网页颜色、表情或排列位置猜测。如果以后 MCP 增加结构化字段，可以带字段来源接入并用真实样本验证，但加红本身仍没有交易授权。

## 分类、确认和预警

“国家队救市”不能只匹配“国家队”三个字，而要同时满足：相关机构或政策主体、资本市场动作、受影响股票/ETF/市场对象。

事件状态为：

`已发现 → 已标准化 → 已分类 → 待官方确认 → 已确认/有冲突/暂时无法确认 → 已映射 → 背景/报告/关键预警 → 已复盘`

进入关键预警前必须回答：

- 这次真正新增了什么？
- 对用户持仓或当前市场计划有什么关系？
- 正向、负向和不确定传导是什么？
- 作用是日内、战术还是长期逻辑？
- 什么证据确认或推翻解释？
- 它改变计划、只提高观察优先级，还是不改变任何行动？

未获得官方确认的重大线索可以保留，但不能取得决策权。任何事件都不能绕过红色风险否决或缺失的持仓数据。

## 失败处理

- Token 缺失：明确数据源不可用，不泄露凭据；
- `isError=true`：按业务错误处理；
- JSON-RPC `error`：按协议错误处理并清洗错误信息；
- 缺少 `structuredContent`：解析失败，不拿 `content` 顶替；
- 当日额度耗尽：停止该工具调用，保留最后成功时间并标记过期；
- 超时或会话丢失：有限重试一次并重新初始化，禁止无限等待；
- 分页异常：保留已取数据并明确覆盖不完整；
- 官方来源冲突：展示冲突并阻止需要确认的预警升级。

## 核心验收

- 产品 MCP 客户端不依赖 Codex 配置；
- Token 全链路不泄露；
- 机器只解析 `structuredContent`，分页契约正确；
- 列表、搜索和晚间汇总不会产生重复预警；
- 体育或产业“国家队”不会误判为市场救市；
- 国新500亿元和诚通近百亿元两条案例的累计/未来语义判断正确；
- 关键事件保留官方确认状态，金十本身不能授权交易；
- 持仓优先，无持仓时不强制生成候选标的；
- 限流、超时、过期、分页不完整和来源冲突全部可见；
- JSON 与启用的 Markdown/HTML/预警表面结论一致；
- 周日/日内汇总能够校漏并关联原子事件，不产生重复事件或重复预警；
- MCP 没有重要/加红字段时保持未知、明确缺口，不根据视觉或文字猜测；
- 聚焦测试、全量回归、真实产物、项目记忆、Harness 和秘密扫描通过。

## 后续节奏

首个实现只做快讯、文章详情、日历、重要消息汇总识别与校漏、标准化、有限事件分类、确认状态和报告内影子输出。只有在重复率、误报率、漏报、延迟和来源可靠性有证据后，才启用主动关键预警。

如果该层不能提高重大事件召回或减少人工核验时间，反而增加低价值提醒，就合并为后台研究输入或暂停。
