# InsightRadar V0.02｜单股决策分析 MVP 产品需求文档

> **PRD-V0.02.2｜2026-11-09｜FROZEN / 已确认**  
> 适用：个人使用、本地运行的 A 股单股决策辅助。  
> 本文是产品验收基准；技术实现见 `02_TECH_技术设计_实施版.md`。未经产品负责人再次明确批准，不增加功能。

## 0. 决策记录（已拍板，不要再反问）

| 问题 | 冻结结论 |
|---|---|
| 看盘时点 | 仅使用最新**已完成且可确认终值**的日 K；盘中不混入实时价格 |
| 观察计划有效期 | **方案 A：D 日冻结，严格只验证下一个交易所开放日 D+1，未触发则过期；不顺延** |
| 观察状态更新 | 用户点击分析、主动打开历史/复核计划时获取；不后台盯盘、不通知 |
| 保存 | 每次完成或部分完成的分析自动生成不可变快照；后验判定另追加记录 |
| 官方公告 | 最近 90 个自然日可检索公告 + 最新已披露定期报告，优先重大事项；覆盖不足明确披露 |
| 数据不足 | 哪部分缺，哪部分降级；UNKNOWN 不等于风险不存在 |
| 账户 | 仅本地单用户，V0.02 不做登录/注册/权限；服务只绑定 localhost |
| 行情成本 | **免费优先，不购买 Tushare**；BaoStock 本地接入，已有同花顺 Fuyao 可作候选补充但需要本地访问验证 |
| 交易权限 | `trade_authority=none`，永远不自动买卖，不生成买入许可 |

## 1. 产品目标与用户故事

用户输入一个沪/深/北 A 股普通股证券代码，系统基于真实、可复核的数据，在**一个股票分析页面**回答四个问题：

1. **趋势**：截至最近已完成日 K，当前为 `UP`、`DOWN`、`MIXED` 还是 `UNKNOWN`？证据是什么？
2. **价格**：可观察的支撑/压力区间是哪里？候选基准和 ATR 半宽怎么算？若无效则说“无清晰区域”。
3. **条件**：只有一种“趋势回踩”买入观察规则；D 日先冻结区间，再由 D+1 的完整日 K 验证。卖出方面只有两根有效日 K 跌破各自 MA55 的人工复核提示。
4. **风险**：最近官方公告、最新已披露定期报告里有哪些最多 5 条关键事实、解释与可能的正负影响？下一次哪些事实可以推翻或支持当前判断（最多 3 条）？

**交付体验：** 不要求用户理解策略细节才能阅读结论；任何结论都能在页面上看到数据时点、公式/依据、原文出处与覆盖缺口。

## 2. 范围边界

### V0.02 必须完成

- 支持输入 6 位沪深北普通 A 股代码，也可输入已确认的交易所后缀；由证券主数据唯一匹配身份。
- 最近目标 120 根已完成、有效的**前复权日 K**；同时保留原价、原始时间、价格基准与来源，核验交易日历/停牌/复权。
- 程序计算 MA20、MA55、ATR14、趋势、候选支撑压力及相关有效性。
- 根据 TECH-R1 形成有明确生命周期的 D+1 买入观察计划；展示卖出复核条件与状态。
- 官方渠道检索 90 日可检索公告（自然日）+ 最新一期已披露定期报告，以 LLM 提炼最多 5 条关键事实/风险、最多 3 个未来核验点，关键事实逐条有官方原文定位。
- 在同一页面展示趋势、价格区域、条件、事件风险；能看到来源、截止时间、缺口及“为什么”。
- 完成或部分完成报告自动保存为不可变快照；历史可查看；D+1 后验结果仅追加。
- 支持股票未知、数据不齐、停牌、未收定、来源故障、LLM 失败等准确降级。

### 明确不做

实时盯盘、分钟线、委托/自动下单、全市场自动选股、大盘预测、板块排行、仓位管理、持仓同步、回测平台、自动策略优化、多智能体、KOL 跟单、完整研报全文搜索、OCR 大规模扫描件识别、多用户系统、通知推送、商业公开部署。

## 3. 端到端流程

```text
输入证券代码
  → A. 证券身份唯一确认 + 数据资格审查
  → B. TECH-R1 程序计算（指标/趋势/价区/冻结观察计划/卖出复核）
  → C. 官方公告与最新定期报告 → 文本提取 → LLM 结构化事实/风险/反证
  → D. 独立状态合并；技术与事件证据可以相互矛盾，不合成总分
  → E. 报告快照保存；打开历史可人工触发已有 D+1 计划后验验证
```

**绝不允许：** LLM 算技术数值、基于盘中未收定数据判断、用二手观点冒充官方事实、把异常/未知补成 0 或“无风险”、用 D+1 K 线回写 D 日决策。

## 4. 规则 TECH-R1（业务口径，程序唯一权威）

### 4.1 数据基准

- 交易时区 `Asia/Shanghai`，只使用确认为完整终值的日 K。
- 以**有效交易 K**（非停牌填充值）序列按日期升序计算；原价/前复权价、复权锚点、交易日历与异常原因可见。
- 目标 120 根有效已完成日 K；不足 120 可降级展示；完整趋势最少需要 **60 根**（含 MA55 当前与 5 根前）。
- 历史数据不足、冲突或尚未终值确认时，受影响结论必须 `UNKNOWN`；不得自动构造今日假 K。

### 4.2 趋势分类

```text
UP   : C > MA20 > MA55，且 MA20(t)>MA20(t-5)，MA55(t)>MA55(t-5)
DOWN : C < MA20 < MA55，且 MA20(t)<MA20(t-5)，MA55(t)<MA55(t-5)
MIXED: 数据完整但不满足 UP 或 DOWN
UNKNOWN: 数据不足、口径冲突、最新数据未确认完整
```

所有大于/小于均为**严格不等号**，等于不满足。

### 4.3 支撑、压力和价区

候选中心为 MA20、MA55、最近 20/60 个有效交易日最高价及最低价。`P=最近已完成收盘价`，候选中心 `< P` 中最近者为支撑；候选中心 `> P` 中最近者为压力；等于 P 的不参与。区间半宽固定 `0.5×ATR14`，上下沿等于中心 ± 半宽。

ATR14 使用 Wilder 平滑（具体起始种子见技术文档），严格使用当前数据快照计算，不允许浏览器或 LLM 二次解释数值。

如果 ATR、候选、价格基础不可靠，或支撑区上沿 `>=` 压力区下沿，则输出“无清晰区域”，附具体原因。不得输出盈利目标价。

### 4.4 买入观察：方案 A（唯一研究方式：趋势回踩）

**建立计划 D：** 只有 `trend=UP` 且存在有效支撑区时，冻结 `planId`、证券身份、基准交易日 D、支撑区上下沿、复权口径/锚点与规则版本。D 日不能用当日 K 来宣布“买入条件已满足”。

**验证 D+1：** 固定为 D 之后**下一个交易所开放日**（不是下一个有成交的交易日；停牌不能顺延）。当 D+1 收定、数据有效且价格尺度可比：

- D+1 最低价 `>= 冻结下沿` 且 `<= 冻结上沿`；
- D+1 收盘价 `> 冻结上沿`；
- D+1 收盘价 `> D+1 开盘价`。

全部满足，状态 `TECHNICAL_CONDITION_MET`（**仍然不是买入权限**）。若 D+1 收盘 `< 冻结下沿`，状态 `INVALIDATED`。其他已完成且可核验结果为 `EXPIRED_NO_SIGNAL`。如果交易日未结束，保持 `WAITING_NEXT_BAR`；若 D+1 停牌/缺数据/复权不可比，状态 `NEEDS_RECHECK` 或 `ADJUSTMENT_CHANGED_RECHECK`，该计划**不顺延**。迟到数据只能补验同一个 D+1，不得迁移到 D+2。

**后续失效：** 已满足观察条件后，之后某个已完成交易日收盘 `< 旧计划冻结下沿`，可追加 `INVALIDATED_AFTER_TRIGGER` 复核记录；不得修改当初的 `TECHNICAL_CONDITION_MET` 或快照。

### 4.5 卖出复核

两个连续交易所开放日 D-1/D，分别满足 `close < 当日 MA55`，标记 `PRICE_RISK_REVIEW`。两天必须都完成、有效、可比；中间停牌不能跳过交易日拼接。事件风险由 LLM 分开显示 `EVENT_RISK_REVIEW`，绝不自动决定仓位、止损价或订单。

## 5. LLM 的职责与证据规则

### 5.1 提炼（最多 5 条）

在官方原文中输出 `statement`、`classification`（已披露事实/公司解释/模型推断）、`impact`（正向/负向/混合/不确定）、`whyItMatters`、`asOf` 和可核对的 `documentId / page / quote / officialUrl`。不可定位引用的条目不得进入正式结论。最新财报有明确的重要反证时，不能只挑利好。

### 5.2 未来核验（最多 3 项）

每项包含问题、可能的证据来源、清晰判定标准、预计验证时点（未知可标未知），统一 `manualConfirmationRequired=true`。LLM 生成核验条件不会自动变成交易规则。

### 5.3 覆盖声明

展示检索区间、发现文档数、处理数、PDF 抽取失败数、分页完备性、报告期及最终覆盖状态（`COMPLETE | PARTIAL | UNAVAILABLE`）。`COMPLETE` 仅表示在**声明范围内**目录与处理完整，不代表全市场消息无遗漏；不能推出“没有重大风险”。

## 6. 页面与交互（只有一个主页面）

### 顶部

- 股票代码输入、唯一证券身份、`开始分析`。
- 展示当前报告生成时间、**行情基准日**、来源与数据状态。
- 出现失败时给短明确说明和可重试动作；无效证券拒绝且不给股票猜测。

### 区域一：趋势

大号状态 `UP/DOWN/MIXED/UNKNOWN` + 最近已完成收盘、MA20、MA55、ATR14、规则解释、120 根 K 线/均线图。图表、标签和数字都从同一个后端报告读取。

### 区域二：价格

支撑/压力的中心、区间、候选来源、半宽依据及“现价相对区域”的说明。任何“不存在/重叠/不足”以中文“无清晰区域”呈现，不放虚构点位。

### 区域三：条件

一张买入观察计划卡：生成 D、截止 D+1、冻结价区、条件逐条状态、后验结果及“仅观察，非交易指令”。另一张卖出复核卡：连续两日 MA55、当前触发/未触发/未知。

### 区域四：风险

最多 5 条影响摘要（按事实性质与影响方向可辨识）、每条可展开原文引用和官方 PDF；最多 3 条未来核验点。即使 LLM 失败也能看到公告标题清单和覆盖缺口。

### 页脚

折叠详情：来源/错误/缺失数据、日 K 的复权口径、算法版本、LLM 版本、输入/结果指纹；可打开历史列表/只读快照和计划验证记录。

**原型**：`../prototype/index.html`，为**离线交互演示**、数据全是模拟，不是实盘/正式数据服务；只用于页面验收。

## 7. 错误与降级

| 情况 | 产品行为 |
|---|---|
| 非法/不存在证券 | `INVALID_SECURITY`，拒绝；不猜代码/交易所 |
| 仅 59 根有效日 K | 可展示已有价格与部分 MA，完整趋势 `UNKNOWN` |
| 最新日 K 未终值或数据过期 | 明确截至哪天；阻断新的有效观察计划 |
| 交易日历或复权矛盾 | 受影响技术状态不可用，列出冲突证据；不混拼来源 |
| D+1 停牌或数据缺失 | 不判成未触发，不顺延到 D+2；允许 D+1 迟到数据补验 |
| 官方目录不可用/漏页/抽取失败 | 技术分析正常；事件覆盖 `PARTIAL/UNAVAILABLE` |
| LLM 超时或 JSON/引用校验失败 | 不虚构摘要；保留官方原文列表和明确失败原因 |
| 无有效支撑/压力 | “无清晰区域”，买入计划等待条件，不制造信号 |
| 技术条件满足但风险覆盖不全 | 并列两个独立状态，绝不升级为买入许可 |

## 8. 验收标准

1. 证券身份唯一、可核验，覆盖沪/深/北普通 A 股；对缺失覆盖提供真实状态，不能谎称支持。
2. MA20、MA55、Wilder ATR14、价区与独立参考计算一致；程序结果与 UI 一致。
3. 59/60/61 根 K、严格等号、平盘、停牌、跨除权、未收定、早期上市、重叠价区均有测试。
4. D 日生成计划不能提前判断 D+1；D+1 成功、失效、未触发、停牌、资料迟到均可复算；只验固定 D+1。
5. 卖出复核不跨跳停牌日或未收定数据；只给复核不下单。
6. 每一条 LLM 关键事实能够定位到官方 PDF 页与原句，发现的重大反证不会被静默丢弃。
7. 来源失败和数据缺口明确降级；未知不会被显示成“没有风险”。
8. 同样的输入、模型输出存档、资料版本和规则版本能够复现报告；重复分析产生新快照，不覆盖历史。
9. 使用至少 10 只不同技术状态、交易所和异常类型的**真实股票**完成验收，零严重错误；至少 8 份能给出可核验结论或明确、有用的降级说明。
10. 可在 macOS 本地按 README 启动；服务仅绑定 localhost，无真实令牌泄漏；1440×900 和 390px 两种页面尺寸可阅读。

**验收不包括收益/胜率**。研究条件成立 ≠ 策略已证明有盈利优势。

## 9. 三个切片与停止条件

- **切片一｜确定性技术链路**：证券身份 → 免费行情/质量 → TECH-R1 → 价区 → 冻结 D+1 → 后端 REST → 主页面。真实数据验收通过才叫完成。
- **切片二｜可溯源风险**：官方公告/最新定期报告 → PDF → LLM → 证据校验 → 风险卡片。失败保持技术功能可用。
- **切片三｜快照与交付**：不可变历史、追加式 D+1 评估、异常/边界回归、10 股真实验收。

三个切片通过即停止本版开发。发现范围外需求记录为候选，不在当前版本做。
